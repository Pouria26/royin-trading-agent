# حساب اعتباری و قرارداد اجرای مالی

وضعیت جاری: **BUY_UNKNOWN / اجرای مالی عمومی بسته است**. این مرجع عملیاتی را پیش از تغییر ارسال سفارش، reconciliation یا state حساب بخوانید.

## چه چیزی بررسی شده؟

تلاش فنی `e7d8bc5` یک POST، یک DELETE و شش GET با همان شناسه داشت. پاسخ بدنهٔ POST خالی بود؛ وضعیت HTTP آن در نسخهٔ قدیمی ذخیره نشد و قابل بازسازی نیست. استعلام‌های بعدی not_found دادند؛ آن را FILLED یا REJECTED گزارش نکنید.

بررسی تازهٔ خواندنی: هویت حساب اعتباری فعال مطابق تنظیمات، TMN آزاد ۵٬۰۰۰٬۰۰۰، قفل صفر، USDT صفر؛ تاریخچهٔ بدون فیلتر با `has_more_pages=false` خالی، سفارش باز صفر و همان شناسه `404`. زیان یا سفارش قابل مشاهده‌ای پیدا نشده؛ علت تاریخی پاسخ خالی و finality آن هنوز تأیید نشده است.

کاربر تأیید کرده کلید جایگزین از داخل حساب اعتباری ساخته شده و مجوز معامله دارد. این تأیید را دوباره سؤال نکنید؛ منشأ حساب اصلی یا نبود مجوز را علت اثبات‌شده ندانید. خواندن موفق API به‌تنهایی موفقیت POST را ثابت نمی‌کند.

## مسیر موجود و محدودیت

`CreditCanaryTransport` فقط USDTTMN LIMIT، یک BUY و یک SELL، سقف debit خرید ۱۰۰٬۰۰۰ TMN و هشت درخواست سفارش در کل را می‌پذیرد. preflight حداکثر ۱۸ خواندن دارد. این اعداد سیاست داخلی همین canary هستند، نه حداقل عمومی صرافی یا راه‌حل سودآور AI. درخواست‌های تشخیصی بعدی، جدا ثبت شده‌اند و شمارندهٔ آن مسیر را reset نکرده‌اند.

state حساب در `~/.royin-credit-state/<account-sha256>/canary.sqlite3` و قفل مشترک در `~/.royin-credit-locks/` است؛ مستقل از clone. فایل budget مدل نیز در `data/llm-budget.sqlite3` پایدار است. برای شروع دوباره هیچ‌کدام را حذف، کپی-reset یا دستی ویرایش نکنید. reserve و intent قبلی حفظ می‌شوند؛ retry با ID تازه مجاز نیست.

نسخهٔ فعلی، status HTTP را پیش از خواندن/تفسیر بدنه ثبت می‌کند. payload، header و پاسخ خام خصوصی وارد log عمومی، ویدئو، مدل یا Git نمی‌شوند. چند clone روی یک میزبان باید همان قفل حساب را رعایت کنند؛ برای دو دستگاه، یک مالک اجرا لازم است.

## دستور امن بررسی

از ریشهٔ پروژه؛ پیش‌فرض shadow بماند:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.execute_credit_canary --help
.\.venv\Scripts\python.exe -X utf8 -m scripts.execute_credit_canary --prepare
.\.venv\Scripts\python.exe -X utf8 -m scripts.probe_wallex_account --run
```

prepare و probe خواندنی‌اند و Secret محلی می‌خواهند؛ نمونهٔ اجرای موفق قبلی، تأیید آماده‌بودن آینده نیست. تغییر `RUN_MODE=live` به‌تنهایی مسیر عمومی ایجاد نمی‌کند. `--execute` را برای دور زدن وضعیت فعلی یا ساخت canary تازه تکرار نکنید.

## قواعد واقعی و مجهول‌ها

- snapshot عمومی spot برای USDTTMN مقدار `minNotional=50000`، `minQty=0.01`، stepSize=2 و tickSize=0 داشت؛ step/tick تعداد اعشارند. عدد ۱۰۰ یا ۳۰۰ هزار تومان را حداقل ثابت همهٔ بازارها فرض نکنید؛ metadata تازه و امکان فروش پس از fee/rounding لازم‌اند.
- fee مشاهده‌شدهٔ حساب برای TMN maker=0.0025 و taker=0.003 است. سناریوی کسر fee در base/quote و residual باید صریح بماند؛ تضمین صفر dust نداریم.
- انقضای دقیق بسته، کامل‌بودن snapshot fill، هویت fill و finality حساب باید در مسیر واقعی بررسی شوند. public trades، fill حساب خصوصی نیستند.
- فقط حساب اعتباری اختصاصی؛ حساب اصلی، برداشت، واریز، انتقال، فعال‌سازی اعتبار و leverage در scope نیستند. منطق مدل نمی‌تواند این مرز را تغییر دهد.
- پیش از اجرای الگوریتم واقعی: قرارداد بازیابی intent فعلی، transport محدود و نسخه‌دار، قواعد بازار/fee، ثبت ACK/fill و تطبیق مانده، stop/deadline و شواهد استراتژی لازم‌اند. موفقیت یک تست فنی، تأیید alpha نیست.

منابع قرارداد: [معرفی اسپات](https://developers.wallex.ir/docs/spot-intro)، [ثبت سفارش](https://developers.wallex.ir/docs/spot-create-order)، [فهرست سفارش‌ها](https://developers.wallex.ir/docs/spot-order-list). نبود سفارش در چند مشاهده، پاسخ HTTP مفقود گذشته را بازسازی نمی‌کند.
