# دسترسی بازار حساب اعتباری — به‌روزرسانی ۲۰۲۶-۱۰-۲۱

## منبع و دامنه

**R / توضیح مستقیم پوریا:** چالش فقط اسپات و بدون لوریج است. **منبع ارائه‌شده توسط کاربر:** متن «تمام بازارهای والکس به استثنای بازارهای زیر در حساب معاملاتی قابل معامله هستند» و فهرست بازارهای غیرفعال، همراه تصویر مقایسه حساب اصلی/اعتباری. URL صفحه و تاریخ انتشار فهرست ارائه نشده؛ اعتبار همین snapshot برای حساب اختصاصی هکاتون باید پس از دریافت کلید با داده حساب تطبیق داده شود. این مجهول به معنی نیاز به یک فهرست مثبت دستی تازه از پوریا نیست.

نسخه دقیق فهرست ارسالی در [config/wallex-credit-market-policy.json](../config/wallex-credit-market-policy.json) ذخیره شد: **۳۴۵ جفت یکتا، ۱۷۱ جفت TMN و ۱۷۴ جفت USDT**؛ ترتیب منبع حفظ شده است. هیچ بازار تازه‌ای به آن اضافه یا از آن حذف نشده است. این snapshot منبع محدودیت است، نه allowlist ثابت بازارهای فعال.

## قواعد لازم برای Coding Agent

1. فقط Spot بدون margin، leverage، borrow و موقعیت short. SELL صرفاً از دارایی قابل فروش همان حساب؛ فروش بیشتر از موجودی آزاد پس از fee و سایر رزروها ممنوع. اعتبار اولیه مسابقه مجوز گرفتن وام/اعتبار اضافی یا فعال کردن پکیج دیگر نیست.
2. مجموعه مجاز اجرایی از **بازارهای اسپات شناخته‌شده و فعال صرافی ∩ بازارهای قابل استفاده حساب اختصاصی − اجتماع ممنوع‌های snapshot، محدودیت تازه حساب و محدودیت اضافه برگزارکننده** ساخته شود. اگر داده حساب فقط unavailableMarkets می‌دهد، مکمل فقط نسبت به catalog تأییدشده همان حساب/پکیج گرفته شود؛ قرارداد/داده ناکافی ورود live را می‌بندد. به universe تاریخی یا داده عمومی مجوز حساب نسبت ندهید.
3. `WALLEX_ALLOWED_MARKETS` فقط زیرمجموعه انتخابی برای اجراست؛ override قوانین بالا نیست. حتی نماد داخل این متغیر، پاسخ مدل یا metadata عمومی اگر در ممنوع‌هاست رد شود. بدون انتخاب معتبر، live هنوز بسته است. محدودیت خاص هکاتون در صورت اعلام اعمال شود؛ برای همه بازارها اجازه جداگانه از کاربر نخواهید.
4. فهرست در سطح **pair** است، نه coin. برای نمونه `YFI/USDT` آمده ولی `YFI/TMN` نیامده؛ این به معنی ممنوعیت خودکار همه جفت‌های YFI یا مجاز بودن قطعی جفت تومانی نیست. `PAXG/TMN` و `PAXG/USDT` هر دو در ممنوع‌ها هستند؛ استراتژی طلای PAXG در universe فعلی قرار نگیرد.
5. منبع شکل `BASE/QUOTE` دارد؛ در قرارداد API معمولاً نماد بدون `/` است. mapping از base/quote و symbol واقعی metadata انجام شود؛ برای همین snapshot تبدیل مانند `PAXG/TMN → PAXGTMN` با حفظ کامل base قابل استفاده است. صفر/عدد ابتدای نام مثل `1BBABYDOGE` و `2Z` حذف نشود؛ fuzzy match، تبدیل alias حدسی و افزودن quote فرضی ممنوع.
6. قبل از سفارش و بعد از refresh/restart، وضعیت بازار و حساب دوباره بررسی و نسخه/hash محدودیت‌ها در run manifest ثبت شود. محدودیت تازه محدودکننده‌تر مقدم است؛ پاسخ ظاهراً باز API نباید snapshot ممنوع را بی‌مدرک کنار بزند. اگر بازار موقعیت موجود غیرفعال شد، ورود متوقف و امکان خروج از مسیر مجاز بررسی/گزارش شود؛ مسیر ممنوع را برای liquidation دور نزنید.

## برداشت از تصویر

در تصویر ارائه‌شده، حساب اعتباری برای معامله پیشرفته، خریدوفروش آنی و ساخت/مدیریت API علامت تأیید دارد؛ برای معامله تعهدی، بات معامله‌گر داخلی، واریز/برداشت و انتقال بین حساب‌ها علامت عدم پشتیبانی دارد. تصویر به عنوان مدرک ارائه‌شده توسط کاربر خوانده شد؛ دسترسی واقعی حساب مسابقه هنوز آزموده نشده است.

**تفسیر با اتکا به بریف:** «بات معامله‌گر» نام قابلیت داخلی والکس است؛ تیک نداشتن آن را ممنوعیت نرم‌افزار خارجی متصل به API نمی‌گیریم، چون خود بریف اجرای الگوریتم با API/MCP را خواسته و تصویر API را پشتیبانی می‌کند. این استنتاج، تست دسترسی حساب را جایگزین نمی‌کند. مسیر منتخب فعلی سفارش‌گذاری اسپات است؛ پشتیبانی آنی در تصویر الزام به افزودن broker آنی ایجاد نمی‌کند.

## پذیرش T02 / T05 / T06

- fixture حساب و catalog، همراه این snapshot، universe مثبت و قابل استناد بسازند؛ unknown/inactive/denied به action/symbol مجاز تبدیل نشود.
- نماد ممنوع با slash و نماد API متناظر، از هر دو quote، حتی اگر داخل env یا پیشنهاد مدل است رد شود؛ نمونه‌ها: OP و PAXG و AAPLX و 1BBABYDOGE.
- snapshot قدیمی و restriction تازه حساب با اجتماع ممنوع‌ها ترکیب شوند؛ refresh یا restart restriction را پاک نکند.
- SELL بدون دارایی، quantity بیشتر از مقدار قابل فروش، margin/borrow/leverage و مسیر انتقال رد شوند؛ SELL دارایی موجود، «short» نامیده نشود.
- تست‌های فعلی فقط درستی ذخیره snapshot را می‌سنجند؛ **گیت اجرایی بازار و حساب هنوز ساخته نشده است** و باید هنگام پیاده‌سازی در همه حالت‌های historical/shadow/live همان قانون را مصرف کند. داده تاریخی خارج از universe مسابقه فقط پژوهش جداگانه است و نتیجه قابل اجرای مسابقه معرفی نشود.
