# WAIT واقعی، خطای محاسباتی و اتصال مصرف مدل — ۲۵ اکتبر ۲۰۲۶

## نتیجهٔ قابل تأیید

در بررسی ۰۶:۴۵ تهران، مأموریت اصلی `RUNNING` است؛ **هیچ سفارش یا fill واقعی جدید ندارد**. این نتیجه هنوز هدف مالی پروژه را برآورده نمی‌کند. مدل واقعی BoxAPI پاسخ می‌دهد؛ فعال‌بودن برنامه و تعداد تست، شاهد سود یا موفقیت اجرای خرید نیست.

در ۱۲ trace با index اصلی ۱۱۷..۱۲۸، ده `MODEL_DECISION/WAIT` و دو `HOST_FALLBACK` ثبت شده‌اند. نامزدها در هر چرخه ۵..۹ مورد و ظرفیت قابل بررسی ۲..۶ مورد بوده است. هیچ‌کدام از این تعدادها به معنی فرصت سودآور نیستند. آخرین چرخه پیش از اصلاح، هزینهٔ حدود ۱٫۱۲٪ برای TRX و ۱٫۰۴٪ برای BTC را بالاتر از پیش‌بینی مرکزی می‌دید؛ TRX علاوه بر آن محدودیت حداقل/باقیمانده داشت.

## خطای قطعی و اصلاح موتور

Trace۱۲۳ پیش از HTTP دوم با `InvalidOperation` متوقف شده بود. بازپخش آفلاین context اصلی، خطا را در `_serialize_model_context → display` بازتولید کرد: نامزد SUI دارای `EV_VOLUME_PRESSURE_UNAVAILABLE` و متن معتبر `volume proxy=None` بود، اما serializer تلاش می‌کرد `Decimal("None")` بسازد. نبود فشار حجمی می‌تواند حاصل کندل‌های تخت یا نبود حجم قابل محاسبه باشد؛ عدد صفر جایگزین درستی نیست.

فقط این مرز در `src/royin/agent.py` اصلاح شد: sentinel شناخته‌شدهٔ `None` به JSON null می‌رود؛ evidence ID، متن کامل ثبت‌شده، hash و دادهٔ سایر نامزدها حفظ می‌شود. ورودی عددی نامعتبر عمومی پذیرفته نمی‌شود. تست SDK واقعی روی MockTransport نشان می‌دهد نامزد ناموجود، تحلیل نامزد معتبر دیگر را قطع نمی‌کند؛ این تست، معاملهٔ واقعی یا سود نیست. بازپخش همان trace روی سرور جدید `SERIALIZATION_OK` با ۲۴٬۶۶۶ بایت شد، بدون مدل/سفارش تازه.

Trace۱۲۵ به دلیل `DECISION_EVIDENCE_NOT_IN_SNAPSHOT` رد شده بود. این یک خروجی نامعتبر مدل است؛ validator حذف یا ضعیف نشده و evidence بعد از پاسخ جعل/پاک‌سازی نشده است. تکرار این رفتار هنوز یک محدودیت مدل است.

## چرا کارت‌ها نامعلوم بودند

`Sources.overview` در برنامهٔ مستقل ابری، برای رزرو به دیتابیس محلی و برای SDK به فایل review آرشیوی نگاه می‌کرد. هیچ‌کدام در کانتینر داشبورد وجود نداشتند؛ publisher هم این داده‌ها را ارسال نمی‌کرد. نبود اتصال گزارش، نشانهٔ نبود تماس واقعی مدل نبود.

مسیر جدید در `dashboard/model_metrics.py` و publisher، دفتر **اصلی** مدل را صرفاً با `mode=ro`، query_only، timeout کوتاه، محدودیت ردیف و progress handler می‌خواند. هیچ Ledger constructor، migration یا درخواست provider/Wallex ندارد. فقط اعتبار funded انتخاب‌شده جمع می‌شود؛ رزروهای قدیمی همان‌جا محفوظ‌اند. اتصال دادهٔ محلی در `readonly_budget` هر دو schema شناخته‌شدهٔ legacy/funded را می‌پذیرد و ستون ناشناخته را رد می‌کند.

SDK usage از traceهای واقعی دارای usage جمع می‌شود؛ trace بدون usage به صفرِ مصرف تبدیل نمی‌شود. مانیفست با سقف۶۴MiB/۱۰۰۰trace فقط هنگام تغییر reparsed و hash آن منتشر می‌شود. publisher کم‌اولویت، تک‌مالک، بدون کلید مالی/مدل و با سقف حافظه۳۸۴MiB است؛ تنها استثنای قرارداد file-only قبلی، همین SELECT محدود روی DB بودجهٔ مدل است. DB مالی در این مسیر باز نمی‌شود. برنامهٔ داشبورد همچنان هیچ DB/کلید مالی ندارد.

allowlist در publisher و دریافت‌کننده، count/decimal/timestamp و coverage را دوباره بررسی می‌کند. snapshot ناموجود/خراب به عدد صفر ارتقا نمی‌یابد؛ دادهٔ کهنه STALE می‌شود. صورتحساب provider و مصرف جاری کل حساب هنوز دریافت نمی‌شوند و **UNAVAILABLE** می‌مانند.

در پذیرش واقعی ابری ۰۶:۴۳ تهران:

- رزرو اعتبار جدید: **USD۰٫۷۹۷۳۵۲۹۶، ۱۸۳ درخواست، ۶٬۱۸۳٬۹۳۶ توکن رزروشده**؛ معادل صورتحساب یا موجودی provider نیست.
- SDK ثبت‌شدهٔ مأموریت: **۷۸۱٬۵۱۰ ورودی و ۴۵٬۹۲۷ خروجی، ۸۴trace دارای usage از۹۴تلاش واقعی**؛ پوشش ناقص است.
- باقیِ مانیفست شامل traceهای دیگری مانند bootstrap/تعویق میزبان است؛ ۱۳۰trace را ۱۳۰ پاسخ معتبر مدل ننامید.
- HTML/CSS/فونت‌ها و چیدمان تغییر نکرده‌اند. فقط binding متن موجود در JS اصلاح شد: تعداد «تلاش ثبت‌شدهٔ مأموریت»، timeout/fallback و پوشش usage از داده می‌آیند؛ عبارت ثابت نامعلوم دیگر جای شمارندهٔ موجود قرار نمی‌گیرد. میانگین latency با helper موجود به‌صورت تقریبی کوتاه نمایش داده می‌شود. مرورگر تازه در۱۴۴۰/۳۹۰px کارت‌های واقعی را با AVAILABLE، timeout/fallback برابر۰/۱۷ و coverage برابر۸۴/۹۴ رندر کرد؛ خطای صفحه/overflow مشاهده نشد و هر دو فونت بار شدند. یک navigation با timeout۳۰ثانیه هنگام بررسی ثبت شد؛ اجرای تازه با DOMContentLoaded و سپس networkidle در هر دو viewport موفق بود؛ خطای قبلی حذف نشده است.

## validation و محدودیت

۵۶۸تست هسته در۷۰٫۴۷۴ثانیه و۳۱تست داشبورد در۸٫۷۶۹ثانیه PASS؛ Ruff کل src/scripts/tests/dashboard، compileall و diff-check پاس. دو viewport واقعی ابری و مسیر HMAC→projection→HTTP روی دادهٔ واقعی بررسی شدند؛ نبود auth۴۰۱، جزئیات کلید/پاسخ خام منتشر نشد. هیچ commit یا push ساخته نشد؛ HEAD همان۶۹۳f1f4است.

گراف MCP در index/search/coverage با Transport closed در دسترس نبود؛ بررسی روی منبع دقیق و callerهای مرتبط انجام شد، ادعای پوشش کامل graph نداریم. ابزار عمومی UX kit ابتدا بیرون از root خودش۰/۵۲ و در root خودش۱۲/۵۲ گزارش کرد؛ dependency/Playwright و تعدادی harness خود kit آماده نیستند. این self-test نه امتیاز محصول رویین است و نه PASS جامع دسترس‌پذیری؛ UI/UX کامل بازطراحی/ممیزی نشده است. پذیرش واقعیِ محدود این تغییر، HTTP/auth، دادهٔ صفحه، فونت و عدم overflow/error در دو viewport فوق است.

آخرین تصمیم تازهٔ نسخهٔ جدید `MODEL_DECISION/WAIT` با دوHTTP۲۰۰ است؛ سابقه، بودجه و اجرای واحد ادامه دارند، اما **خرید، فروش، round-trip و سود واقعی هنوز تأیید نشده‌اند**. خطای فنی مشخص رفع شده؛ مزیت اقتصادی استراتژی از این کار نتیجه نمی‌شود. اصلاح بعدی باید از سنجش انتخاب بازار/forecast با baseline و هزینهٔ واقعی بیاید، نه از ساخت سفارش اجباری برای نمایش فعالیت.
