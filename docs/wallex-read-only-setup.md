# شناسه حساب اعتباری والکس

«ساب‌اکانت» حساب فرعی است، نه sub-agent هوش مصنوعی. [مستند رسمی](https://developers.wallex.ir/docs/trade-credit-active-sub-account-list) و Swagger اعتبار، `GET https://api.wallex.ir/sub-accounts` را برای فهرست حساب‌ها و `clientId` را برای شناسه معرفی می‌کنند. مقدار clientId در `SUB_ACCOUNT_CLIENT_ID` داخل .env و هدر `sub-account-client-id` استفاده می‌شود؛ از عدد قبل از `|` در API key ساخته نمی‌شود.

**مشاهده واقعی ۲۰۲۶-۱۰-۲۱:** کلید ارائه‌شده در .env ذخیره و GET احرازشده موفق شد؛ success=true ولی result=[] بود. این پاسخ فقط نبود حساب فرعی قابل مشاهده با همین کلید را نشان می‌دهد؛ غلط بودن کلید، تأیید حساب مسابقه یا زمان تخصیص اعتبار از آن نتیجه نمی‌شود. هیچ شناسه‌ای حدس زده نشد و هیچ دارایی حساب اصلی خوانده نشد.

پس از اینکه برگزارکننده حساب اختصاصی را تخصیص داد، همین دستور را از ریشه مخزن اجرا کنید؛ کلیدها نیاز به ارسال مجدد ندارند:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.probe_wallex_account --run
```

اگر دقیقاً یک حساب فعال و غیرمعلق از نوع prop موجود باشد، ابزار clientId را در .env می‌گذارد و فقط balances-detail آن را می‌خواند. چند حساب، پاسخ ناقص، حساب غیرفعال یا نبود دسترسی، BLOCKED می‌دهد؛ اگر چند حساب بود فقط شناسه حساب مسابقه را محلی انتخاب کنید. raw و گزارش در data/private ignored هستند و مشخصات حساب در خروجی چاپ نمی‌شود.

این مرحله فعال‌سازی اعتبار نمی‌کند و مسیر POST/DELETE ندارد. اگر فهرست پس از تخصیص همچنان خالی بود، پوریا از برگزارکننده تطبیق کلید/حساب اختصاصی را بخواهد؛ برای تست، حساب شخصی یا طرح اعتبار تازه فعال نکنید. fee، min-order، محدودیت روز حساب، تعلق حساب به مسابقه و موجودی اولیه هنوز باید با همان حساب تأیید شوند؛ موفقیت خواندن موجودی مجوز معامله نیست.
